# Fraud detection - AutoML vs manual model, from training to serving

Two fraud-detection models follow the same MLOps path: training, registration
in the MLflow Model Registry, promotion with a `production` alias, REST serving,
and latency measurement from an external client.

- **AutoML**: FLAML, 90 s budget -> XGBoost classifier
- **Manual baseline**: Random Forest, 500 trees, depth 16

## Results

| Criterion          | Manual (RF 500/16) | AutoML (FLAML, XGBoost) |
|--------------------|--------------------|-------------------------|
| F1 (test set)      | 0.8669             | 0.8582                  |
| Median latency     | ~56 ms             | 8-25 ms                 |
| p95 latency        | 100-220 ms         | ~33 ms                  |
| Model size         | 13.37 MB           | 0.29 MB                 |

**Decision:** the AutoML model goes to production. It gives up about 1 % of F1
but is 46x smaller with a stable, much lower p95 latency. The manual model stays
in the registry, so a rollback is a single alias change.

## Stack

Python 3.13 - FLAML - scikit-learn - XGBoost - MLflow (tracking, registry, serving)

## Project structure

- `src/automl_deploy.py`: AutoML search, export and registration (fraude-automl)
- `src/modele_manuel.py`: manual baseline, registration (fraude-manuel)
- `src/promouvoir.py`: sets the production alias on the latest version
- `src/client.py`: REST client, 200 timed calls, median and p95
- `reports/`: comparison table and FLAML search log

## Run it

    python -m venv .venv; .venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    python donnees.py
    mlflow server --host 127.0.0.1 --port 5000 --backend-store-uri sqlite:///mlflow.db --default-artifact-root ./mlartifacts
    python src/automl_deploy.py
    python src/modele_manuel.py
    python src/promouvoir.py fraude-automl
    python src/promouvoir.py fraude-manuel
    mlflow models serve -m "models:/fraude-automl@production" -p 8100 --env-manager local
    python src/client.py 8100

The dataset is synthetic and regenerated by `donnees.py` (fixed seed), so no data is versioned.
